## これは何のためのものか

NAS、自宅サーバー、カメラ、自分で立てたサイト——どれも外からは届きません。家庭用ルーターにグローバル IP がないからです。

OpenFrp は安い VPS を玄関にしてこれを解決します。訪問者の通信はまず VPS に届き、ルーターが張り続けているトンネルを通って LAN 上の機器へ運ばれます。

```
訪問者 ──▶ あなたの VPS(グローバル IP) ──トンネル──▶ ルーター ──▶ NAS / サーバー / カメラ
```

必要なものは二つです。

- **OpenWrt が動いているルーター**。パッケージと Web 画面はここに入ります。
- **グローバル IP を持つ VPS**。事業者も規模も問いません。一番安いもので足ります。設定時に一度だけ SSH を使います。

ドメインは任意です。なければ `IP:ポート` でアクセスし、あれば `nas.example.com` と本物の HTTPS が使えます。

## インストール

ルーターでコマンドを一つ実行します。

```bash
wget -O - https://raw.githubusercontent.com/zoefix/openfrp/main/scripts/install.sh | sh
```

アーキテクチャを判別し、対応するリリースを選び、公開されているチェックサムと照合し、この機械で実際に動くことを一度確かめてからインストールします。足りない依存パッケージは `apk` か `opkg`（システムが使っている方）で導入されます。

同じコマンドをもう一度実行すればアップグレードです。削除するには:

```bash
wget -O /tmp/openfrp-install.sh https://raw.githubusercontent.com/zoefix/openfrp/main/scripts/install.sh
sh /tmp/openfrp-install.sh --uninstall
```

設定は残るので、入れ直せば同じトンネルがそのまま使えます。設定・証書・通信量の記録もまとめて消すには `--purge` を使ってください。

その他のオプション: `--version v0.4.0` で特定のリリース、`--lang ja` で翻訳も同時に、`OPENFRP_API=…` で github.com に届かない環境向けのミラー指定。

そのあと **LuCI → サービス → OpenFrp** を開きます。メニューが出ていなければ一度ログアウトして入り直してください。

## 設定の手順

### 手順 1 — VPS を用意する

**サーバー** タブで **サーバーを追加** を押し、次を入力します。

| | |
|---|---|
| アドレス | VPS の IP |
| SSH ユーザー | たいてい `root` |
| SSH パスワード | ここで初めて聞かれます。保存にチェックしなければ残りません |

**SSH でデプロイ** を押します。VPS 側にサーバーが入ります。ディストリビューションと init システムを判別し、バイナリを転送し、サービスを書き、ファイアウォールを開けて起動するところまで自動です。30 秒ほどで、ログはその場に流れます。

終わると接続トークンが自動で入ります。**ステータス** タブでサーバーが接続済みになっているはずです。

> すでにその VPS で OpenFrp が動いている場合は、デプロイを飛ばしてアドレス・ポート・トークンを手で入力してください。

### 手順 2 — トンネルを追加する

**トンネル** タブで **追加** を押し、種類を選びます。

| 種類 | 用途 | アクセス方法 |
|---|---|---|
| **HTTP** | Web サイト、NAS の管理画面など、ブラウザで開くもの | `https://nas.example.com` |
| **TCP** | SSH、データベース、Minecraft、リモートデスクトップ | `VPS のアドレス:ポート` |
| **UDP** | ゲームサーバー、WireGuard、DNS | `VPS のアドレス:ポート` |

**HTTP** トンネルで入力するもの:

- **ローカルアドレス / ポート**——サービスが実際に動いている場所。例えば `192.168.1.50` と `5000`。
- **ドメイン**——訪問者が使う名前。例えば `nas.example.com`。
- **HTTPS を有効化**——443 でも提供します。

**TCP** と **UDP** では代わりに **リモートポート** を指定します。VPS 側のどのポートをサービスへ転送するか、ということです。

**有効** にチェックを入れて **保存して適用** を押します。

### 手順 3 — ドメインを VPS に向ける

DNS 事業者側で `A` レコードを作ります。

```
nas.example.com.   A   <VPS の IP>
```

あるいはワイルドカードにすれば、配下の名前を一つずつ登録しなくても届くようになります。

```
*.example.com.     A   <VPS の IP>
```

反映を待って——たいてい 1〜2 分——`http://nas.example.com` を開くと、サービスが見えるはずです。

### 手順 4 — HTTPS 証明書を取得する

**証明書** タブで **証明書を申請** を押し、ドメインを入れて送信します。`nas.example.com` のような通常の名前なら他に何も要りません。名前はすでに VPS を指しているので、VPS 自身が認証局からの確認に応答します。

**ワイルドカード**（`*.example.com`）は別です。認証局が DNS 認証を要求するため、先に **DNS** タブで DNS 事業者の API 認証情報を登録してください。対応: Alibaba Cloud、DNSPod、Huawei Cloud、Cloudflare、NameSilo、PowerDNS、West。

発行できたらトンネルを編集し、**TLS の扱い** を *リモートサーバーが HTTPS を処理* にして証明書を選びます。接続を切らずに VPS へ配布され、更新も自動で行われます。

## ドメインの振り分け

同じ VPS 上で、いくつトンネルがあっても 80 と 443 を共有し、リクエスト中の名前で振り分けられます。ワイルドカードに対応しており、`*` は**ちょうど 1 階層**を表します。

| 書き方 | 一致する | 一致しない |
|---|---|---|
| `aaa.com` | `aaa.com` | サブドメイン全般 |
| `*.aaa.com` | `www.aaa.com`、`nas.aaa.com` | `x.bb.aaa.com` |
| `*.bb.aaa.com` | `x.bb.aaa.com` | `y.x.bb.aaa.com` |

完全一致の名前は常にワイルドカードより優先されるので、`*.aaa.com` を一つのトンネルに、`shop.aaa.com` を別のトンネルに向けられます。

これは DNS と HTTPS 証明書の規則と同じです。`*.aaa.com` の証明書は `www.aaa.com` を含みますが `x.bb.aaa.com` は含みません。同じ規則にしてあるので、入力された名前を証明書がカバーしていないトンネルへ訪問者が振り分けられることは起こりません。

## よくある構成

**Web 管理画面付きの NAS**——HTTP トンネル、ローカルポート `5000`、ドメイン `nas.example.com`、HTTPS を有効化し、手順 4 で証明書を取得。

**自宅マシンへ SSH**——TCP トンネル、ローカル `192.168.1.10:22`、リモートポート `2222`。接続は `ssh -p 2222 ユーザー@VPSのアドレス`。

**ゲームサーバー**——UDP（ゲームによっては TCP）、ローカルポートはサーバーが待ち受けているもの、リモートポートも同じ番号にしておけば、参加者に別の番号を伝えずに済みます。

**1 台の VPS で複数サイト**——サイトごとに HTTP トンネルを 1 本、それぞれ自分のドメインを設定。443 は共有され、追加の設定は要りません。

## 帯域制限とトラフィック

トンネルごとに、その編集画面で制限できます。

- **下り制限**——訪問者へ向かう方向、単位 KB/s。`0` で無制限。
- **上り制限**——訪問者から来る方向、単位 KB/s。
- **トラフィック上限**——双方向の合計、単位 MB。到達するとそのトンネルは新しい接続を受け付けなくなります。月間転送量の決まった VPS で有用です。

**ステータス** ページにはトンネルごとの現在の上下速度が表示され、日ごとの合計は 400 日分保存されます。

## 更新について

**ステータス** ページに動作中のバージョンが表示されます。新しいリリースがあると隣にボタンが出て、押すと変更内容が表示され、確認を求められます。

更新はすべてを入れ替えます——クライアント、サーバーのバイナリ、Web 画面、翻訳——そしてサービスを再起動します。新しいバージョンが起動しなかった場合は自動的に元のバージョンへ戻すので、問題のあるリリースでルーターのトンネルが全部止まることはありません。

コマンドラインから更新したい場合は、インストーラーをもう一度実行すれば同じことになります。

## うまくいかないとき

### サーバーが未接続と表示される

原因として最も多いのはファイアウォールではなく、**ルーター上の透過プロキシ**です。OpenClash、Passwall、ShellCrash はいずれも外向き TCP をすべてリダイレクトするため、トンネルの制御接続まで巻き込まれ、それを中継できないノードへ送られてしまいます。

見分け方ははっきりしています。ログでは接続に成功した直後に切断され、VPS 側のログには何も残りません。

直し方は二つ、どちらでも構いません。

- そのサーバーの編集画面で **プロキシを迂回** を有効にする。
- あるいはプロキシの設定で、最後の全体ルールより前に直結ルールを足す:
  ```yaml
  - "IP-CIDR,<VPS のアドレス>/32,DIRECT,no-resolve"
  ```

### ドメインを開くと「この名前を提供しているトンネルがありません」と出る

リクエストは VPS まで届いているので、DNS は正しいということです。トンネルが有効になっていないか、その名前が **ドメイン** 一覧に入っていないかのどちらかです。`*.example.com` は `a.b.example.com` を含まない点に注意してください。

### 証明書の申請が失敗する

通常のドメインなら、まずその名前が VPS を指しているか確認してください。認証局がそこへ到達できる必要があります。ワイルドカードの場合は **DNS** タブの認証情報を確認します。**テスト** ボタンで使えるかどうか分かります。

### サービスが訪問者を全員ルーターとして記録する

トンネルの **クライアント IP** を有効にし、サービス側でそれを信頼するよう設定します。nginx の場合:

```nginx
listen 5000 proxy_protocol;
set_real_ip_from <ルーターの LAN アドレス>;
real_ip_header proxy_protocol;
```

**先にサービス側を設定してください**。PROXY プロトコルのヘッダーを受け取る準備ができていないサービスは、この設定を有効にした瞬間からすべてのリクエストを拒否します。

### DNS と証明書のページが利用不可と表示される

この二つには SQLite が必要ですが、MIPS 向けのビルドがありません。トンネルには影響せず、すべての種類がそのまま使えます。ルーター上で証明書を管理できないだけです。

## アンインストール

```bash
sh /tmp/openfrp-install.sh --uninstall
```

インストール時に記録した一覧をもとに、自分が入れたファイルだけを削除し、サービスを停止・無効化します。`/etc/config/openfrp` は残るので、入れ直してもトンネルの設定はそのままです。完全に消したい場合は手で削除してください。

VPS 側は、デプロイ画面の **削除** でサーバーをきれいに取り除けます。

## 開発者向け

```bash
make build       # 両方のバイナリ。静的リンク、CGO なし
make check       # vet、gofmt、レース検出付きテスト
make test-linux  # Linux 上でのテスト。splice(2) が実際に効くのはそこだけ
make bundle      # インストーラーと更新機能が使うリリースバンドル
```

重要なのは `make test-linux` です。ゼロコピーに関する検証は macOS では飛ばされます。`splice(2)` が Linux にしかないからです。
